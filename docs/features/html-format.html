The HTML format — one page, two readers

Status: shipped (0.2.0) · Read when: changing src/html.ts, the page format, <pre class="pseudo">, <pre class="verbatim">, <pre class="mermaid">, feature_map_upgrade, or what a page looks like in a browser

What it does

  • A feature page is an HTML document under docs/features/; index.html is the index. The agent never receives the markup — every reply is the page rendered to compact canonical text (#/##/###, bullets, fences) — while a person opens the same file, follows its links and sees its graphs.
  • Headings remain the retrieval unit: h1 is the title, h2 a section, h3 a subsection, so splitSections() and every reply level work unchanged.
  • A code-shaped block is <pre class="pseudo"> by default: an agent copies the shape, not the bytes. <pre class="verbatim" data-why="…"> is only for a block whose exact bytes matter, and the reason is mandatory.
  • A graph is <pre class="mermaid">; the browser draws it from a CDN loader and the reader hands an agent the edge list instead of the source.
  • A legacy Markdown map (docs/features/README.md plus .md pages) is still read forever. feature_map_upgrade writes the HTML siblings, and the HTML page wins when a stem has both.

How & why

What is measured

Bytes are measured on the rendered text, never on the markup. A page's text field is what htmlToMapText() produced, and every size, rank, cap and reply uses it. That is what keeps the format from spending the agent's budget on class attributes: the browser pays for the markup, the agent does not.

The reader

The reader is a tokenizer, not a DOM. tokenize() walks tags and comments; the walker understands the vocabulary the plugin writes (h1–h6, p, ul, ol, li, pre, table, blockquote, dl, inline code/strong/em/a) and treats anything else as a paragraph boundary. head, script, style and title are skipped as raw text — without that, the stylesheet is read as the page's first paragraph and the mermaid loader as prose.

Round-tripping is pinned, not assumed. renderMapDocument() and htmlToMapText() are inverses for the canonical vocabulary: headings, bullets, tables, fenced pseudo/verbatim/mermaid, status paragraphs. A parser change that loses a table row or turns one list into three fails the round-trip test before it reaches a reply.

The code policy

verbatim without a reason is a defect. scanHtml() reports it, the converter writes a visible TODO reason, and feature_map_check names the page under On code:. Pseudocode converted from a language is reported too: the fence keeps its language in data-from-lang, so a reviewer can see what was copied and decide what the block was meant to teach.

The upgrade

The upgrade is additive. It writes .html beside each .md, rewrites internal .md links, and leaves the source in place unless prune: true. A project that runs it can still be read by an older checkout, and deleting the legacy file is an explicit choice rather than a side effect. force is the only way an existing .html is replaced.

One plan, one shape. planUpgrade() returns the same keys whether or not there is a map: the absent plan (absent: true, no docs/features/) carries flagged: [] and verbatim: [] rather than omitting them, because the tool reads plan.flagged.length before it ever looks at absent. An earlier version returned a shorter object and threw undefined is not an object on the one case the branch exists to report.

The graph

Graph in the format:

flowchart LR
  MD[README.md + pages.md] --> UP[feature_map_upgrade]
  UP --> HTML[index.html + pages.html]
  HTML --> READ[reader: canonical text]
  HTML --> BROWSER[browser: styles + graph]
  LEGACY[legacy .md kept] --> READ

The section

A section is still the unit of review. The HTML writer emits one section per ## heading with an id, but the reader ignores the id and re-derives the slug from the heading. Renaming a heading moves the anchor; the reply label (page#section) moves with it, and no stored map has to be migrated.

Config keys / UI

No new plugin options. The upgrade's arguments are per call:

ArgumentDefaultEffect
applyfalseReport the plan only; with true, write the .html files.
prunefalseAlso remove each .md source once its sibling is written.
